### 3.21 Messaging channels

The `messaging` value of `screen` opens `MessagingScreen` (`web/src/components/Messaging.tsx`) from More in the primary navigation (3.1). It shows the supported Telegram, Discord, Slack and WhatsApp channels exposed by the phone's Hermes engine. Channel settings are profile-scoped. The app does not display saved secret values; generic Settings → Keys and Advanced settings continue to omit channel-managed fields (3.15).

**Load and channel list:** on open or Refresh, `GET /api/messaging/platforms` loads the platform rows and filters them to `telegram`, `discord`, `slack` and `whatsapp`. Loading shows the shared `Status` state. A failed request shows `LoadError` and Retry. An empty result says that this engine version has no supported channels. Each channel card shows its name, description, gateway state and an enable/disable button. Expanding a card shows its configured fields and actions. State labels distinguish connected, disabled, setup needed, restart needed, stopped, failed and disconnected.

**Channel setup:** fields are rendered with password input for secrets and text input for non-secret values. A saved secret is represented by “Saved securely”; the actual value is never returned to the screen. Clear queues removal until the user confirms; Save setup sends only non-empty drafts and requested clears with `PUT /api/messaging/platforms/<id>`. Test connection sends `POST /api/messaging/platforms/<id>/test` and shows its returned message. A channel-provided `docs_url` opens its setup guide outside the app. Changes that need a restart show a banner and a Restart gateway action; the restart asks for confirmation, calls `POST /api/gateway/restart`, then refreshes status.

**WhatsApp linking:** the card can start either phone-number pairing or QR pairing, and either bot mode or self-chat mode. Pairing method and connection mode use the app's `SelectRow` / `PickerSheet`, not native `<select>` controls. Phone mode requests a phone number with country code. `POST /api/messaging/whatsapp/onboarding/start` creates a pairing session; while it is starting or waiting, the screen polls its pairing route at a bounded 1.2 second interval and stops on a terminal state or when the screen state changes. It shows a pairing code when supplied, otherwise it renders the QR payload as a QR image. The user can cancel with `DELETE /api/messaging/whatsapp/onboarding/<pairing_id>`. On connection, Save and connect applies the mode at `/apply`, refreshes channels and reports whether a gateway restart started. Starting another pairing after a linked phone asks for confirmation.

The QR payload is generated locally in the screen with `qrcode`; the screen renders no personal chat content. Starting, waiting, connected, error and expired states are shown; cancelling clears the pairing view. All visible labels use `navigationText` for Arabic and English; phone numbers and pairing codes retain left-to-right direction in RTL.
