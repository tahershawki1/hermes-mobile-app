# خطة تنفيذ تصميم واجهة Hermes Mobile

## الهدف

تنفيذ الاتجاه البصري الموجود في لوحات المعاينة على شاشات Hermes Mobile كلها، مع الحفاظ على سلوك التطبيق الحالي، ورسائل Hermes، والصلاحيات، والتنقل والإيماءات. التنفيذ سيكون تدريجيًا على فرع المراجعة، وتُراجع لقطات كل مرحلة قبل اعتمادها.

## خط الأساس

- المستودع المحلي وفرع GitHub `codex/hermes-chat-review` متزامنان الآن عند `2dfc1d10`.
- هذا الفرع مبني على مسودة PR 42؛ لا يستهدف `main` مباشرة.
- لوحات المعاينة الـ17 موجودة محليًا في `/workspace/hermes-mobile-ui-review/`، وتعرض الاتجاه الداكن وتسميات إنجليزية. أُنشئت عند `1f8d6e34` قبل إضافة تدفق رمز الهاتف في `2dfc1d10`؛ لذلك تحتاج لوحة Messaging إلى تحديث قبل تنفيذها. بقية اللوحات مرجع بصري وليست مواصفة نصية نهائية.
- التنفيذ سيحافظ على الترجمة الحالية للإنجليزية والعربية، واتجاه RTL، والسمات الداكنة وOLED والفاتحة وسمات النظام.
- طلب المستخدم السابق بإظهار قنوات Telegram وWhatsApp يجعل شاشة القنوات ضمن النطاق الحالي. يوجد تعارض معها في `docs/decisions/app-is-the-only-front-end.md` و`docs/spec/03-20-shared-ui-kit-hard-ui.md`؛ تُحدّث هذه المراجع في المرحلة المناسبة حتى تعكس القرار الأحدث.

## حالة التنفيذ

- بدأ التنفيذ على فرع المراجعة: أضيفت متغيرات ذهبية دلالية مشتركة وحلقة تركيز موحدة للأزرار، واستُخدمت في التنقل وبطاقات الوجهات.
- استُبدلت قائمتا اختيار ربط واتساب بعنصر `SelectRow` ولوحة الاختيار المخصصة. توثّق الآن شاشة Messaging في المواصفة 3.21، ويحل قرار القنوات الجديد محل المنع السابق لواجهة القنوات.
- لا تزال بقية المراحل واللوحات المرجعية قيد التنفيذ؛ لوحة Messaging القديمة لا تطابق مسار رمز الهاتف بعد.

## مبادئ التنفيذ

1. **نغيّر العرض قبل السلوك:** لا تتغير واجهات Hermes أو تدفقات API أو صلاحيات الهاتف ضمن عمل التصميم، إلا إذا ظهر عائق وظيفي واضح.
2. **نبني من عناصر مشتركة:** كل الشاشات تستخدم الغلاف والصفوف والبطاقات والأزرار والحقول واللوحات الموجودة في `Screens.tsx` و`ui.tsx` بعد تحسينها؛ نتجنب نسخ تنسيقات مختلفة لكل صفحة.
3. **نحافظ على قواعد المستودع:** الألوان عبر CSS variables، والحقول والقوائم والحوارات بعناصر التطبيق، لا بعناصر النظام أو حوارات المتصفح.
4. **نصمم للهاتف أولًا:** عرض أساسي 360–390 px، ومساحات لمس لا تقل عن 44 px، مع تخطيط التابلت عند 700 و840 px.
5. **نغطي الحالات الفعلية:** التحميل، البيانات الفارغة، الخطأ، الانقطاع، الإيقاف، النجاح، والطلب المعلّق بحسب كل شاشة.
6. **نحافظ على الإيماءات:** Back، درج الجلسات، السحب للأرشفة والحذف، Canvas، وBy the way لا تتغير أثناء تجميل الواجهة.

## مراحل التنفيذ

### المرحلة 0 — مطابقة المعاينات مع النسخة الحالية

- مراجعة الشاشات الفعلية على الفرع `codex/hermes-chat-review` بعد آخر تحديث، ومقارنة بنية كل شاشة بلوحات المعاينة.
- حصر كل قيم `Screen` وكل اللوحات الجانبية والحوارية من المواصفة، وتحديد أي عنصر تغير منذ إنشاء الصور؛ وتحديث لوحة Messaging لتطابق تدفق رمز الهاتف الحالي.
- تثبيت قائمة النصوص والبيانات التجريبية لكل لقطة؛ لا تظهر أي مفاتيح أو بيانات شخصية.
- توحيد قرار قنوات المراسلة في وثائق التصميم والمواصفة كما ورد في خط الأساس.

**المخرج:** قائمة شاشات وحالات نهائية، مع أي فروق مع الصور موضحة قبل لمس CSS.

### المرحلة 1 — نظام التصميم والغلاف المشترك

- ضبط متغيرات اللون، الخط، التباين، المسافات، الحواف والطبقات في `web/src/styles.css` و`web/src/theme.ts`.
- تطوير عناصر `web/src/components/ui.tsx`: الصف، القسم، الزر، المفتاح، اختيار القيمة، التحكم المقسّم، ولوحة الاختيار.
- تحسين `ScreenShell` والتحميل والخطأ والحالة الفارغة في `web/src/components/Screens.tsx`.
- توحيد حالات التركيز والضغط والتعطيل، و`prefers-reduced-motion`، ومناطق الأمان في Android.

**المخرج:** عناصر قابلة لإعادة الاستخدام تظهر متناسقة في كل السمات دون تغيير تدفق الشاشة.

### المرحلة 2 — التنقل والرئيسية والجلسات

- تحديث الترويسة وشريط التنقل السفلي في `Navigation.tsx` و`Navigation.css`.
- تنفيذ Home وSessions وWork وKnowledge وMore، مع ترتيب المعلومات والبطاقات الواضحة كما في اللوحات 02 و08.
- تحسين درج الجلسات والبحث والمجموعات والمثبتات وحالة العمل في `Drawer.tsx` و`SessionList.tsx` و`ChatHome.tsx`.
- الحفاظ على التنقل بين Home والجلسة وعدم تفريغ المحادثة عند فتح صفحة أخرى.

**المخرج:** تنقل واضح للشاشات الخمس، مع قائمة جلسات سهلة المسح والاستخدام بيد واحدة.

### المرحلة 3 — المحادثة والكتابة

- تحسين شاشة المحادثة الفارغة والنشطة، شريط الحالة، رسائل المستخدم وHermes، نشاط الأدوات والملفات المتغيرة.
- تطوير الحالات الست لمربع الكتابة، ومرفقاتها وقائمة Add، والإملاء، والإرسال دون اتصال، وSteer وQueue.
- مراجعة الصفحات/العناصر في `App.tsx` و`ChatItems.tsx` و`Composer.tsx` و`ChatHome.tsx` دون تغيير بروتوكول الرسائل.
- مراعاة العربية في الرسائل والاقتباسات والجداول والكود والمحتوى المختلط الاتجاه.

**المخرج:** لقطة فارغة، ولقطة محادثة جارية، ولوحة حالات للمربع متوافقة مع التصميم.

### المرحلة 4 — مساحة العمل والمحتوى

- تحديث Hermes hub وSkills وMemory وScheduled jobs وFiles وProjects وCanvas gallery وBots.
- تصميم تفاصيل المهارة، إنشاء/تحرير مهمة مجدولة، معاينة الملف، تفاصيل المشروع وتحرير ملف الوكيل.
- استخدام نمط موحد للبحث والفلاتر والصفوف والبطاقات، مع حالات تحميل وخطأ ونتائج فارغة.
- الملفات المتوقعة: `Screens.tsx` و`Bots.tsx` و`Gallery.tsx` والمكونات المرتبطة بكل صفحة.

**المخرج:** كل وجهات Work وKnowledge وصفحات Hermes قابلة للفهم دون كثافة بصرية زائدة.

### المرحلة 5 — النماذج والإعدادات والقنوات

- تنفيذ Settings وAppearance وVoice وSpeech recognition وDefault models وModel providers وAPI keys وHermes settings وAdvanced.
- تحديث اختيار النموذج، تفاصيل المزود، تسجيل الدخول برمز الجهاز، نقطة الاتصال الخاصة، والتدوير الاحتياطي.
- تحديث Bot-scoped settings مع توضيح الملف النشط والنموذج المستخدم.
- تحديث واجهة Messaging وWhatsApp pairing ضمن النطاق المعتمد، مع مراجعة رسائل الأمان وعدم عرض الأسرار.
- الملفات المتوقعة: `Settings.tsx` و`HermesSettings.tsx` و`Providers.tsx` و`Rotation.tsx` و`Connect.tsx` و`SignIn.tsx` و`Messaging.tsx`.

**المخرج:** شاشات إعدادات قابلة للمسح والتعديل، ولوحات تسجيل دخول واختيار متسقة بصريًا.

### المرحلة 6 — التجهيز والحالات الحساسة

- تحسين Setup check وتسلسل Set up Hermes ونقطة اختيار النموذج وصفحة Almost done.
- عرض تقدم تثبيت Termux وShizuku وHermes بوضوح، مع أخطاء قابلة للفهم وإعادة المحاولة.
- مراجعة لوحات الموافقة والأسئلة وكلمة المرور، وشاشة إلغاء تثبيت Hermes؛ تبقى الأفعال الخطرة منفصلة وواضحة.
- الحفاظ على كون طلب الموافقة غير قابل للإغلاق حتى الإجابة، كما تحدد المواصفة.

**المخرج:** تدفق تجهيز مفهوم للمستخدم الجديد، وحالات موافقة لا تخفي أثر الإجراء.

### المرحلة 7 — Canvas والصوت واللوحات المساندة

- تحسين Canvas في العرض والتحرير والتعارض، ولوحة المستند الجديد وتخطيط التابلت.
- تحسين Live mode في الاستماع والتفكير والتحدث، ومشغل القراءة الصوتية.
- تحديث By the way، قوائم المحادثة، Context، Goal، Status، File checkpoints، Lightbox والحوارات.
- الحفاظ على ترتيب الطبقات وسلوك Android Back لكل لوحة.

**المخرج:** الشاشات الثانوية تبدو من نفس النظام ولا تغطي عناصر المحادثة أو أزرارها.

### المرحلة 8 — التابلت وإمكانية الوصول

- ضبط التخطيطات عند 700 و840 px، والدرج المثبت وCanvas بجانب المحادثة، وإخفاء العمود واستعادته.
- مراجعة جميع الشاشات بالإنجليزية والعربية، وبسمات Dark وOLED وLight وSystem، وعند تكبير النص.
- مراجعة التباين، أسماء الوصول، ترتيب التركيز، أحجام الأهداف، لوحة المفاتيح، تقليل الحركة، والتمرير الطويل.

**المخرج:** تجربة مستقرة على الهاتف والتابلت، دون قص أو تداخل أو اعتماد على اللون وحده.

### المرحلة 9 — التحقق والمراجعة

- بعد كل مجموعة شاشات: تشغيل typecheck وفحوص المشروع المطلوبة، وإضافة فحص متصفح موجّه لكل تغيير ويب وفق `AGENTS.md`.
- تحديث ملف المواصفة المعني لكل تغيير UI، وسجل التغييرات المرئية عند انطباقه، وقرار قنوات المراسلة المتعارض.
- التقاط صور من التطبيق الفعلي ومقارنتها باللوحات المرجعية؛ تُعدّل الصور أو التنفيذ إذا تغيرت النصوص أو تدفقات الاستخدام.
- تسليم كل التغييرات على `codex/hermes-chat-review` ومراجعتها في هذه المحادثة؛ لا دمج إلى `main` قبل مراجعة المستخدم.

**المخرج:** فرع جاهز للمراجعة، مع قائمة واضحة بما نجح وما يحتاج اختبارًا على هاتف حقيقي.

## ترتيب الأولوية

1. الغلاف والنظام البصري المشترك.
2. التنقل والجلسات والمحادثة ومربع الكتابة.
3. إعدادات النماذج وصفحات Hermes الأساسية.
4. إعداد التطبيق والموافقات والقنوات.
5. Canvas والصوت واللوحات الثانوية.
6. ضبط التابلت وإمكانية الوصول والمراجعة النهائية.

## شروط القبول

- كل شاشة ظاهرة في لوحات المعاينة لها صفحة تنفيذية أو حالة محددة في التطبيق.
- لا تتغير قدرات التطبيق أو واجهات Hermes بسبب إعادة التصميم.
- لا تفقد المحادثة محتواها أو موضعها عند التنقل بين الصفحات.
- تعمل جميع الشاشات في العربية RTL والإنجليزية، وفي السمات الأربع، وعلى الهاتف والتابلت.
- تظل الحقول والحوارات واللوحات ضمن لغة Hermes البصرية، مع حفظ قواعد الموافقات والإيماءات وAndroid Back.
- تُحدّث المواصفة والفحوص المرتبطة بكل مجموعة قبل طلب مراجعة المستخدم.

## خارج النطاق

- إضافة ميزات Hermes جديدة أو تغيير APIs أو صلاحيات Android.
- دمج التغييرات في `main` قبل مراجعة المستخدم.
- اعتبار نصوص الصور المولدة نصوصًا نهائية؛ مصدر النص النهائي هو التطبيق والمواصفة المعتمدة.
